# Сервис модерации объявлений

Небольшой HTTP API на Python и FastAPI. Принимает данные объявления и возвращает, есть ли в нём нарушение.

## Установка и запуск

Нужен Python 3.9 или новее. Все команды выполняются из корня проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
fastapi dev
```

В Windows вместо `source .venv/bin/activate`:

```powershell
.venv\scripts\activate
```

Сервис: [http://127.0.0.1:8000](http://127.0.0.1:8000).

Документация с формой для отправки запросов: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

## Проверка объявления

`post /predict` принимает JSON. Все поля обязательны.

| Поле | Тип | Ограничение |
| --- | --- | --- |
| `seller_id` | `int` | Больше нуля |
| `is_verified_seller` | `bool` | `true` или `false` |
| `item_id` | `int` | Больше нуля |
| `name` | `str` | Непустая строка |
| `description` | `str` | Непустая строка |
| `category` | `int` | Больше нуля |
| `images_qty` | `int` | Ноль или больше |

Пробелы по краям строк удаляются. Строка из одних пробелов считается пустой. Неверные типы, `null` и неизвестные поля не принимаются: например, строка `"123"` вместо числа вызовет ошибку.

Успешный ответ — одно JSON-значение:

- `true` — есть нарушение;
- `false` — нарушений нет.

Правило проверки:

| Продавец верифицирован | Есть изображения | Ответ |
| --- | --- | --- |
| Да | Да | `false` |
| Да | Нет | `false` |
| Нет | Да | `false` |
| Нет | Нет | `true` |

Название, описание и категория проходят валидацию, но на предсказание пока не влияют.

Пример запроса:

```bash
curl http://127.0.0.1:8000/predict \
  --header 'content-type: application/json' \
  --data '{
    "seller_id": 1,
    "is_verified_seller": false,
    "item_id": 100,
    "name": "велосипед",
    "description": "в хорошем состоянии",
    "category": 10,
    "images_qty": 0
  }'
```

Ответ: `true` со статусом `200`.

## Ошибки

- `400` — неверный JSON, типы или значения полей, отсутствует обязательное поле. В `detail` возвращается список ошибок валидации.
- `500` — внутренняя ошибка сервиса или репозитория. Ответ: `{"detail": "internal server error"}`. Подробности ошибки записываются в лог сервера.

Для ошибок входных данных настроен статус `400`, как требуется в задании.

`get /` возвращает `{"message": "Hello World"}`.

## Структура

```text
main.py              приложение и обработка ошибок
schemas.py           модель входных данных
routers/predict.py   HTTP-обработчик
services.py          правило модерации
repository.py        хранение результатов в памяти
tests/               тесты
requirements.txt     зависимости
```

Обработчик передаёт данные сервису. Сервис вычисляет результат, сохраняет его через репозиторий и возвращает ответ.

Репозиторий хранит последнее предсказание для каждого `item_id` в словаре. После перезапуска данные теряются. База данных для этого задания не используется.

## Тесты

После установки зависимостей:

```bash
python -m pytest -q
```

Тесты проверяют правило модерации, формат ответа, валидацию входных данных, сохранение результата и ответ `500` при ошибке сервиса или репозитория. Схожие сценарии проверяются с параметризацией.
